# 0. 冻结说明
- 本文件冻结后，V1.0 不再加新功能，只修 Bug、补异常处理。
- 任何新想法进入第 9 节「变更登记」，标 Should / Could，等 V1.0 发布后再评估。
- 判定 Must 的标准：删掉它，主管 AI 还能不能装上、用它完成一个真实编程任务并拿到可信的验收结果？不能 = Must。

# 1. 需求分档

## 1.1 Must（V1.0，少一个就跑不通）

| 编号 | 功能 | 为什么是 Must |
|---|---|---|
| M-01 | 一条命令安装，单二进制（M1 阶段允许 Python 包，M4 换二进制） | 装不上就没有用户 |
| M-02 | CLI，所有命令输出紧凑 JSON | 只有终端的 AI（如 Hark）唯一入口 |
| M-03 | 输出预算：所有返回有上限，截断带续读参数 | 核心卖点「省 token」 |
| M-04 | read（按行段 / 按符号） | 没有就没法看代码 |
| M-05 | search（关键词 + 文件名，内置，不依赖 XERJ） | 没有就找不到代码 |
| M-06 | repo_map（目录 + 主要符号概览） | 新仓库第一步，省大量 token |
| M-07 | edit：唯一匹配替换、失败给最近候选、多文件原子、语法检查拒写 | 核心卖点「改得对」 |
| M-08 | run：超时、结构化结果、输出预算 | 没有就没法跑测试 |
| M-09 | checkpoint：自动快照、回滚 | 改坏了要能撤 |
| M-10 | verify：独立运行验收命令，输出 ≤300 token 报告 | 核心卖点「可信验收」，直接模式也要 |
| M-11 | 直接模式（无模型可用） | 用户明确要求 |
| M-12 | 内置工人循环 + OpenAI 兼容接口 | 用户明确要求接免费 / 付费模型 |
| M-13 | task create / status / wait / report / cancel | 主管派活最小集合 |
| M-14 | 每任务独立 git worktree；工人不能 commit / push | 不让工人弄坏主分支 |
| M-15 | 防作弊基础检查：改测试、改验收脚本、改白名单外文件 | 便宜模型「假装完成」是最大风险 |
| M-16 | 预算硬上限（任务级 token / 金额 / 时间），超了立即停 | 成本封顶 |
| M-17 | 密钥只存引用、不进上下文、日志脱敏 | 泄露 Key 是最严重事故 |
| M-18 | doctor 自检 | AI 自己装、自己排错 |
| M-19 | llms.txt + README | AI 读完能自装 |
| M-20 | 评测脚本（最小 20 题）+ 对照基线 | 不评测就不知道是否真的省 |
| M-21 | 项目记忆（变更 C-01，详见 docs/feature-sources.md 第二节 D） | 工人每次从零摸索仓库，浪费 token |

## 1.2 Should（V1.1–V2，上线后加）
- MCP 服务端（stdio，其后 HTTP）
- task answer / steer / accept / reject / diff
- 模型分档自动路由、429 自动切换到用户配置的下一渠道
- test：只跑受影响测试
- XERJ 可选接入（语义搜索、引用、记忆）
- LSP 符号级跳转 / 引用（借鉴 SolidLSP）
- 卡住检测与自动升档
- 更多防作弊规则：写死返回值、针对测试特判、新增依赖、读密钥文件
- 沙箱（Linux bubblewrap）
- gain 节省统计
- reference 命令（自动执行找参考项目流程）
- 多平台二进制（macOS、Windows）

## 1.3 Could（封存，远期）
- 只读状态网页 / 任务看板
- 多主管协作、团队共享任务队列
- 自动拆任务（主管只给大目标）
- 插件系统
- 云端托管版

## 1.4 Won't（明确不做，写死）
- 不做给人用的 IDE、编辑器插件、聊天界面
- 不训练、不托管、不转售模型
- 不提供多账号轮换、代理池、IP 伪装等绕过平台限额或封禁的功能
- 不自动 push / 部署 / 发布到任何线上环境
- 不收集用户代码或使用数据上传到任何服务器（无遥测，除非用户显式开启，且 V1 不做）
- 不做付费功能、不接支付

# 2. 用户路径

## 2.1 主管 AI 首次使用（直接模式）
1. 读 llms.txt → 执行一条安装命令
2. `agentkit doctor` → 确认可用；无模型配置时提示「直接模式」
3. 进入仓库 → `agentkit repo_map`
4. `search` / `read` 定位 → `edit` 修改 → `run` 跑测试
5. `verify --check "<命令>"` → 拿到验收报告
6. 不满意 → `checkpoint rollback`；满意 → 主管自己决定是否提交

## 2.2 派活模式
1. 配置模型：`agentkit model add`（地址、Key 引用、档位、单价）
2. `agentkit task create`（目标、验收命令、允许改动范围、预算）→ 返回任务 ID
3. 主管去做别的 → `task wait <ID>`
4. 读 `task report`（≤300 token）
5. 通过 → 主管自行合并 worktree 分支；不通过 → 重新派或自己改；可疑 → 拉 diff 人工看
6. `task cancel` 随时叫停

## 2.3 退出 / 卸载
- `agentkit uninstall`：删除二进制、配置、缓存、worktree；保留用户代码，不动 git 历史。
- 明确列出所有写入的路径（见 5.3）。

# 3. 验收标准（Must 逐条）

| 编号 | 验收标准 |
|---|---|
| M-01 | Linux x86-64 干净环境，一条命令 ≤30 秒装完；无 root；M4 后二进制 <30 MB |
| M-02 | 每条命令支持 `--json`（默认）与 `--human`；JSON 有固定 schema，CI 校验 |
| M-03 | 默认上限 2,000 token（按 4 字符≈1 token 估算，可配）；任意输入不超限；截断时 100% 带 `truncated:true` 与 `next` 参数 |
| M-04 | 支持 `file:start-end` 与 `file#Symbol`；二进制文件拒读并提示；>1MB 文件自动分段 |
| M-05 | 10 万文件仓库搜索 <2 秒；结果带 `文件:行号`；默认遵守 .gitignore |
| M-06 | 1 万文件仓库 ≤2,000 token 输出；支持至少 Python、JS/TS、Go、Rust、Java |
| M-07 | 匹配 0 次 / 多次时返回最接近 3 处；多文件补丁任一失败全部回滚；支持语言语法错误时拒写并给出行号；一次成功率在评测集上 ≥99% |
| M-08 | 默认超时 120 秒可配；返回 exit_code、耗时、stderr 尾部优先；超时进程组被杀干净 |
| M-09 | 每次 edit 前自动快照；回滚后文件哈希与快照一致；不依赖用户提交 git |
| M-10 | 验收命令在干净 worktree 里运行；报告固定字段：结论、逐条检查结果、改动文件、花费、可疑标记；≤300 token |
| M-11 | 无模型配置时所有工具可用；task create 返回明确提示而非报错崩溃 |
| M-12 | 至少跑通 3 家 OpenAI 兼容接口（如魔搭、OpenRouter、本地 Ollama）；工具调用格式错误自动修复 1 次 |
| M-13 | task status 输出 <100 token；task wait 支持多个 ID 与超时；守护进程重启后任务状态不丢 |
| M-14 | 工人进程无权执行 git commit / push（命令拦截 + 只读 .git 引用）；任务结束 worktree 可清理 |
| M-15 | 作弊样例库 10 例（V1）检出率 100% |
| M-16 | 超预算 5 秒内停止工人；报告注明「因预算中止」 |
| M-17 | 日志、报告、模型上下文中扫描不到任何已配置 Key 的明文 |
| M-18 | doctor 检查：版本、git、写权限、模型连通性、磁盘空间；每项给修复建议 |
| M-19 | 一个从没见过本项目的 AI 只读 llms.txt 能完成安装和一次 verify（实测） |
| M-20 | 评测一键运行，输出通过率、token、成本对照表 |

# 4. 异常流程（全量）

| 场景 | 处理 |
|---|---|
| 模型接口超时 | 重试 2 次（指数退避）；仍失败 → 切下一渠道（V1.1）/ V1 直接暂停任务并在报告中说明 |
| 模型返回 429 / 额度用完 | 不重复轰炸；读 Retry-After；V1 暂停并上报，V1.1 切用户配置的下一渠道 |
| 模型返回格式错误的工具调用 | 自动修复 1 次；失败计 1 次错误，连续 3 次 → 任务失败上报 |
| Key 无效 / 过期 | 立即失败，提示 `agentkit model test`；不重试 |
| 网络断开 | 工具本地功能照常；工人任务暂停，恢复后继续 |
| 工人卡住（N 轮无新 diff 或重复同一错误） | V1 中止并上报；V1.1 升档模型 |
| 工人超时 / 超预算 | 立即停，保留 worktree 供查看 |
| 守护进程崩溃 | 状态落盘，重启后恢复；运行中的工人标记「中断」，可重跑 |
| 同一任务重复提交 | 按内容哈希去重，返回已有任务 ID |
| 并发超限 | 排队，status 显示排队位置 |
| 磁盘满 | 拒绝新建 worktree，提示清理命令 |
| 验收命令本身报错（命令不存在等） | 结论为「验收无效」而非「不通过」，提示主管修正检查 |
| 仓库有未提交改动 | worktree 基于 HEAD；提示主管未提交改动不在工人视野内 |
| edit 目标文件被外部修改 | 检测哈希变化，拒写并提示重新 read |
| 非 git 仓库 | 直接模式可用（用快照代替）；派活模式拒绝并提示 `git init` |
| 运行命令产生海量输出 | 输出预算截断，完整日志落盘可按需读 |
| 子进程残留 | 按进程组清理；doctor 可列出残留 |

# 5. 合规（适配本项目）

## 5.1 开源许可证
- 本项目拟用 **Apache-2.0**（与 Aider、XERJ 一致；含专利授权；可兼容 MIT 代码）。
- 复用代码规则：MIT / Apache-2.0 / BSD 可复用并保留声明（NOTICE 文件登记）；GPL / AGPL 只借鉴思路；许可证未核实的项目（worker-bridge、LooppooL、Nib、jcode、Choragos、Spewer）核实前不复制代码。
- 贡献者：使用 DCO（提交签名 Signed-off-by），不用复杂的 CLA。

## 5.2 模型平台条款
- 工具只是客户端，用户自带 Key；不内置任何共享 Key。
- 文档写明：用户须遵守各平台条款（如魔搭 API-Inference 非商用、不得对外中转）。
- 不提供绕过限额的功能（见 Won't）。

## 5.3 数据与隐私
- 不上传任何代码或数据（模型调用除外，且发给用户自己配置的接口）。
- 本地写入路径明确列出：二进制、配置（~/.config/agentkit）、状态与日志（~/.local/share/agentkit）、worktree（仓库内 .agentkit/）。
- 日志默认保留 7 天，可配置；卸载全部删除。
- 文档提醒：代码发送给第三方模型前，用户自行确认该模型的数据政策。

## 5.4 安全披露
- SECURITY.md：漏洞私下报告渠道（GitHub Security Advisories）。
- 发布包附校验和；M4 后加签名。

# 6. 第三方依赖清单

| 依赖 | 用途 | 收费 | 额度 / 风险 | 降级方案 |
|---|---|---|---|---|
| GitHub | 代码托管、Releases 分发、CI | 公开仓库免费 | Actions 公开仓库免费额度充足 | 镜像到 Gitee / 自建下载 |
| tree-sitter 及语法包 | 符号、语法检查 | 免费，MIT | 部分语言语法包质量参差 | 无语法包时退化为纯文本模式并提示 |
| ripgrep（或同类库） | 搜索 | 免费，MIT / Unlicense | 低 | 内置简单搜索兜底 |
| git | worktree、快照 | 免费 | 用户机器可能没有 | doctor 提示安装；直接模式用文件快照 |
| 用户的模型接口 | 工人干活 | 视渠道而定 | 免费渠道限流、下架频繁 | 直接模式兜底；多渠道配置 |
| XERJ（可选） | 语义搜索、记忆 | 免费，Apache-2.0；Query-1 模型闭源 | 不可用时功能变弱 | 内置搜索兜底 |
| bubblewrap（V1.1） | 沙箱 | 免费 | 仅 Linux | 其他平台降级为受限进程并明确提示 |

本项目自身无服务器、无数据库、无 CDN、无支付，运行成本为 0（除用户自己的模型费用）。

# 7. 风险评审

| 风险 | 可能性 | 影响 | 应对 |
|---|---|---|---|
| 竞品（Grok Workhorse 等）已占位 | 高 | 中 | 差异化：自带省 token 工具集 + 直接模式 + 轻量；README 首屏写清对比 |
| 省 token 效果不明显 | 中 | 高 | M-20 评测先行；M1 样品就测，不达标就调整方向 |
| 免费模型质量差，派活通过率低 | 高 | 中 | 防作弊 + 打回；混合模式让主管写难的 |
| 工人执行危险命令 | 中 | 高 | worktree 隔离、禁 push、V1.1 沙箱、命令黑名单 |
| Key 泄露 | 低 | 高 | M-17；CI 加密钥扫描 |
| 用户拿去做账号轮换、绕限额 | 中 | 中（声誉、平台封禁） | Won't 写死、不接受此类 PR |
| `curl | sh` 被篡改 | 低 | 高 | 校验和 + 签名 + 固定 Release 地址 |
| 许可证纠纷 | 低 | 高 | NOTICE 登记每段复用代码来源；GPL 不复制 |
| 开源后贡献者少 / 维护压力大 | 中 | 中 | 先做好 CONTRIBUTING、good first issue；范围冻结防止 PR 乱加功能 |
| 个人开发时间不足导致烂尾 | 中 | 高 | MVP 锁 20 个 Must；任务拆到半天一个 |
