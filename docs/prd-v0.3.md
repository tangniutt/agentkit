# 核心设计理念

> **AgentKit 是一个让 AI 自己提建议、持续改进、持续吸收先进工具设计理念的 AI 编程工具。**

使用者是 AI，改进它的主要力量也是 AI。所有功能都服务于这一个自我进化回路：

```
AI 真实使用 AgentKit（直接模式 / 派活模式）
   │  出错或发现更好的设计 → 结果里最多一条 feedback 提示（只在有信号时出现）
   ▼
agentkit feedback --bug / --improve --from <运行ID>      只生成草稿（带脱敏证据），先查重、先问人类，从不自动提交
   ▼
GitHub Issue（ai-feedback）→ 自动初筛（必填段落、疑似密钥、needs-eval）
   ▼
docs/triage.md 评分表：证据、收益、代价、风险 / 兼容、许可证、是否符合 AI 优先 / 省 token / 低内存
   ▼
accepted → 基线第 9 节登记 C-xx → 实现 + 测试 + 评测（合并前量化，数字变差不合并）→ 关闭 Issue 并引用提交
   ▲
定期调研前沿工具设计（省 token、少幻觉、工具调用、内存、搜索与提示词）→ 同一评分表 → C-xx
借鉴开源代码只用 MIT / Apache-2.0 / BSD 并登记 NOTICE；GPL / AGPL / 未核实的只借思路
```

三条硬约束贯穿回路：**证据先行**（每个提案带运行记录或评测数字）、**人类把关**（Issue 公开，提交前先问人类；从不自动提交、自动 push、遥测上传）、**评测守门**（接受的改动必须用测试与 `eval/` 量化，不只凭感觉）。

# 1. 背景与目标

## 1.1 问题
1. **工具不省 token**：现有编程工具给人设计，AI 用起来读太多、改失败、不知道对错。
2. **贵模型干便宜活**：主管级大模型自己读日志、看 diff、跑测试，成本高。
3. **便宜模型不可信**：免费 / 低价模型常「说做完了其实没做完」，主管要么全盘重查（又贵了），要么盲信（出事故）。
4. **安装重**：现有方案多依赖 Node / Python 运行时，云端 Agent 的沙箱里装起来慢、占内存。

## 1.2 目标
一个**单文件、低内存**的编程工具，三种用法：

| 模式 | 谁动手写代码 | 适用 |
|---|---|---|
| 直接模式 | 主管 AI 自己（用本工具的省 token 工具集） | 没配任何模型；或任务太难不适合外包 |
| 派活模式 | 内置工人，接免费 / 付费模型 | 有模型可用，主管只派活和验收 |
| 混合模式 | 难的主管自己写，简单的派工人 | 日常主力用法 |

## 1.3 成功标准（可量化，评测见第 9 节）

| 指标 | 目标 |
|---|---|
| 安装 | 一条命令，30 秒内完成；二进制 < 30 MB |
| 内存 | 空闲 < 50 MB；单个工人运行时 < 200 MB（不含被测项目本身） |
| 直接模式 token | 比 Claude Code / OpenCode 原生工具省 30% 以上，通过率不降 |
| 派活模式主管 token | 主管每个任务平均消耗 < 3,000 token（派活 + 验收） |
| 派活模式质量 | 主管验收后通过率不低于主管自己写 |
| 编辑一次成功率 | ≥ 99% |
| 工人「谎报完成」漏检率 | < 2% |

## 1.4 非目标
- 不做给人用的 IDE 或聊天界面（可以有只读的状态页，v2 再说）。
- 不训练或托管模型，只接用户自己的模型渠道。
- 不提供绕过任何平台额度或封禁的功能（不做账号轮换、不做代理池）。

# 2. 总体架构

```
主管 AI（Hark / 其他 Agent）
   │  CLI（紧凑 JSON）或 MCP
   ▼
AgentKit 守护进程（单二进制）
   ├─ 任务调度：队列、并发、预算、超时
   ├─ 工人循环：精简 Agent，按任务调模型
   ├─ 工具集：read / search / edit / run / test / checkpoint …
   ├─ 验收器：独立运行验收检查，生成证据报告
   ├─ 模型路由：OpenAI 兼容接口，按难度分级、失败降级
   └─ 可选组件：XERJ（代码索引 + 记忆）
```

**关键原则**：工人只能「提交」，不能「宣布完成」。是否完成由验收器独立判定，主管只看验收报告。

# 3. 强制流程：开发前先找参考项目

## 3.1 流程（主管在派活前、或直接模式开工前执行）
1. 把需求提炼成 3–5 个关键词 + 一句话描述。
2. 在 GitHub 搜索，候选不少于 5 个（按相关度、stars、近一年有更新、许可证过滤）。
3. 每个候选标注：相似度（高 / 中 / 低）、许可证、活跃度、可复用部分。
4. 克隆相似度最高的 1–3 个，建索引（用 XERJ 或内置轻量索引）。
5. 写每个模块前先检索参考实现，引用处在代码注释和报告中注明出处。
6. 许可证规则：
   - MIT / Apache-2.0 / BSD：可复用代码，保留版权声明与 NOTICE；
   - GPL / AGPL：只借鉴思路，不复制代码（除非本项目也用 GPL）；
   - 无许可证：只看思路，不复制。

## 3.2 「新赛道」判定与告知
没有「高」或「中」相似度的项目时，必须告诉用户：
- 「没找到接近的开源项目，可能是一块竞争少的新赛道」；
- 搜过的关键词和范围、最接近的 3 个项目及差距；
- 风险提示：也可能是需求不成立或难度高，建议先做最小样品验证。

找到了也要告诉用户：**哪些部分已有人做好（直接用或借鉴），哪些是空白（我们的差异点）**。

## 3.3 本工具自身的调研结论

### A. 省 token 工具集方向

| 项目 | 可借鉴 | 许可证 | 用法 |
|---|---|---|---|
| XERJ | 代码搜索、跳定义、找引用、记忆、输出预算、远程 MCP | Apache-2.0（Query-1 模型闭源） | 作为可选组件接入 |
| Aider | tree-sitter 仓库地图、改完自动 lint | Apache-2.0 | 借鉴代码 |
| SWE-agent | 窗口式读文件、语法错误拒绝写入 | MIT | 借鉴代码 |
| Serena | LSP 符号级查找编辑 | 主体 GPL-3.0，SolidLSP 为 MIT | 只复用 SolidLSP |
| Nib | 按模型家族给不同编辑格式、修复坏掉的工具调用 | 待核实 | 借鉴思路 |
| jcode | 单二进制、空闲约 28 MB | 待核实 | 参考轻量化做法 |

### B. 主管派活方向（v0.2 新增调研）

| 项目 | 已做到的 | 许可证 |
|---|---|---|
| Grok Workhorse | 主管通过 MCP（delegate_task / wait_task / task_result）派活给沙箱里的 Kilo CLI / OpenCode，任意 OpenAI 兼容模型，守护进程自己跑测试，返回简短结构化结果 + diff；工人不能提交 / 推送 | MIT，仅 Linux |
| worker-bridge | MCP 派活给 Codex / Claude Code / OpenCode，独立 worktree，独立验证 diff，并发限制，日志不泄露密钥 | 待核实 |
| LooppooL | 执行 / 验证两类任务；验证者被告知「工人可能撒谎」，必须用工具核实并给证据；按难度分 高 / 中 / 低 三档模型；预算上限 | 待核实 |
| Choragos | 单 Go 二进制；主管只规划不写代码；任务有 ID 上看板，不会悄悄丢失 | 待核实 |
| Spewer | 派活给低价模型，返回「带证据的收据」 | 待核实 |
| orchestrator-worker-bench | 实测：Opus 主管 + Haiku 工人，13 个任务准确率与全 Opus 持平，成本降 55%，耗时多 42% | 评测数据 |

### C. 结论（如实告知）
- **不是空白赛道**。「主管派活 + 独立验收」已有至少 5 个开源项目，Grok Workhorse 与我们最接近。
- **空白在组合**：目前没有一个项目同时做到
  1. 自带一套省 token 的工具集（现有派活项目都是调用别人的 CLI 当工人，工人本身不省 token）；
  2. 直接模式（主管自己用同一套工具）；
  3. 单二进制 + 低内存，云端 Agent 一条命令装好；
  4. 公开、可复现的省 token 评测。
- **策略**：派活与验收部分大量借鉴 Grok Workhorse（MIT）和 LooppooL 的验证思路；差异化做在「工具集省 token + 三种模式 + 轻量」。

# 4. 功能需求：工具集（直接模式与工人共用）

## 4.1 输出预算（所有工具共用）
- 每个返回默认上限 2,000 token，调用方可调。
- 超出时截断，并返回总量、已显示范围、取剩余部分的参数。
- 日志去重、折叠进度条；错误放最前。
- 验收：任意输入下不超上限；截断提示 100% 存在。

## 4.2 edit
- 精确替换，唯一匹配；失败时返回最接近的 3 处及差异。
- 多文件原子补丁：全成功或全不动。
- 弱模型可用行号 / 哈希锚点编辑。
- 编辑后自动语法检查，语法错误默认拒绝写入。
- 返回 diff（受预算约束）+ 新增 lint / 类型错误。

## 4.3 read
- 按行段或按符号读取；大文件自动分段。

## 4.4 search / symbol / repo_map
- 内置轻量实现：ripgrep 级关键词搜索 + tree-sitter 符号表 + 仓库地图。
- 装了 XERJ 时自动切换到 XERJ（语义 / 混合搜索、引用）。
- 结果带 `文件:行号` 和索引是否过期的提示。

## 4.5 run
- 超时、后台任务、稍后取回输出。
- 结构化返回：退出码、stderr 尾部优先、耗时；输出受预算约束。

## 4.6 test
- 只跑受影响的测试，无法判断时跑全部并说明。
- 返回通过 / 失败数、失败用例名、断言差异、关键堆栈 5 行。

## 4.7 checkpoint
- 编辑前自动快照；查看 diff、回滚到任意点；操作幂等。

## 4.8 notes
- 任务笔记（目标、已完成、待办、踩过的坑），读取 AGENTS.md。
- 装了 XERJ 时接入 `/_memory` 做跨会话记忆。

## 4.9 reference
- 执行第 3 节流程，输出「参考项目报告」或「新赛道告知」。

## 4.10 错误信息规范
每个错误必须包含：发生了什么、最可能的原因、建议的下一步调用（含参数示例）。

# 5. 功能需求：派活模式

## 5.1 主管接口（主管只需要这几个）

| 命令 | 作用 | 返回大小 |
|---|---|---|
| `task create` | 提交任务：描述、验收检查、允许改动范围、预算、模型档位 | 任务 ID |
| `task status` | 一行进度：阶段、已花费、是否卡住、是否在等提问 | < 100 token |
| `task wait` | 阻塞等待一个或多个任务结束（带超时） | 同 report |
| `task report` | 验收报告（见 5.4） | < 300 token |
| `task diff` | 按文件按需拉取 diff | 受预算约束 |
| `task answer` | 回答工人的提问 | — |
| `task steer` / `task cancel` | 中途纠偏 / 叫停 | — |
| `task accept` / `task reject` | 合并结果 / 打回重做（附理由） | — |

- 异步：主管派完即可去做别的；`task wait` 让主管省去轮询的 token。
- 并发：每个任务独立 git worktree，互不干扰；全局并发上限可配。
- 提问：工人遇到需要拍板的事发一个问题回来，而不是自己猜。

## 5.2 任务描述格式
```
目标：一句话
验收检查：可执行的命令列表（如 pytest tests/test_login.py；curl … 期望返回 200）
允许改动：文件或目录白名单
禁止：改测试、改验收脚本、加新依赖（可配置）
预算：最多 $0.50 / 20 万 token / 15 分钟
模型档位：低 / 中 / 高 / 自动
```
主管如果不写验收检查，工具要提醒并给出建议检查，而不是默认通过。

## 5.3 内置工人
- 精简 Agent 循环，只用第 4 节工具集。
- 每个模型家族用它最擅长的编辑格式（借鉴 Nib）。
- 自动修复格式错误的工具调用，修不了再算失败。
- 卡住检测：连续 N 轮无进展或重复同一错误，自动升档模型或上报主管。

## 5.4 验收器与报告（最关键）
- 工人提交后，验收器在**干净环境**里独立运行验收检查，不采信工人的自述。
- 报告固定格式，< 300 token：
  - 结论：通过 / 不通过 / 需要人看
  - 验收检查逐条结果
  - 改动文件列表（每个一句话）
  - 花费：token、金额、耗时、用了哪些模型
  - 可疑行为标记（见 5.5）
- 主管默认只看报告；有疑问再用 `task diff` 拉具体文件。

## 5.5 防作弊检查（自动标记）
- 删除或跳过了测试、改了验收脚本、修改了白名单外的文件；
- 写死返回值、针对测试特判；
- 新增依赖、网络调用、读取密钥文件；
- 改动量异常大于任务需要。
被标记的任务结论自动降为「需要人看」。

## 5.6 模型路由与成本
- 接任意 OpenAI 兼容接口：魔搭、OpenRouter、NVIDIA NIM、用户自建 new-api、本地模型等。
- 每个模型配置：地址、Key 引用、上下文长度、并发上限、单价、档位。
- 按任务难度选档；429 / 额度用完时切到用户配置的**下一个合规渠道**；全部不可用时暂停并上报，不硬试。
- 预算硬上限：任务级、日级；超了立即停。
- 遵守各平台条款：工具不提供多账号轮换、代理池等绕过限额的功能。

# 6. 功能需求：直接模式与混合模式
- 未配置任何模型时自动进入直接模式；`task create` 会提示「当前无工人模型，请主管直接使用工具集」。
- 直接模式下，主管通过 CLI 或 MCP 调用第 4 节工具，同样享受输出预算、编辑校验、检查点、验收报告。
- 直接模式也能用验收器：主管写完后运行 `verify`，得到同格式报告，防止自己漏检。
- 混合模式：主管可以把一个大任务拆开，自己写核心部分，其余 `task create` 派出去。

# 7. 非功能需求

## 7.1 轻量与安装
- 单个静态二进制，Rust 或 Go；Linux x86-64 / arm64 优先，其次 macOS、Windows。
- 安装：`curl -fsSL <地址> | sh`，不需要 root，不改系统 PATH 以外的东西。
- 无 Node / Python 运行时依赖；tree-sitter 语法内置常用 10 种语言，其余按需下载。
- 提供 llms.txt：AI 读完即可自行安装、配置、自检。
- `agentkit doctor` 一条命令自检：版本、模型连通性、沙箱是否可用。

## 7.2 接口
- **CLI 优先**：所有功能都有命令行，输出紧凑 JSON（可选人类可读格式），只有终端的 AI 也能用。
- **MCP**：stdio 与 Streamable HTTP；远程模式默认只读、强制 Token。**v0.3 说明：MCP 服务端尚未实现**（代码里没有任何 MCP 部分；基线把它放在 Should，M1 实际只交付了 CLI）。计划见第 14 节：标准库实现的常驻 stdio 服务端（调研实测热调用 5–12 ms、常驻约 24 MB），少量高层工具 + `outputSchema`，CLI 保留为一次性入口。
- 工具 schema 从运行中的服务自动生成，CI 校验，文档不会和实际脱节。

## 7.3 安全
- 工人在沙箱中运行（Linux 用 bubblewrap，其他平台用容器或降级为受限进程并明确提示）。
- 网络白名单：工人默认只能访问模型接口和包管理源。
- 密钥只存引用，运行时注入，不进入模型上下文，不写日志。
- 工人不能 commit / push / 部署，合并由主管 `task accept` 决定；推送、部署、删除需人工批准。
- 日志脱敏：自动遮盖疑似密钥。

## 7.4 可靠性
- 守护进程重启后任务可恢复（状态落盘）。
- 所有操作幂等；重复提交同一任务不会做两遍。

## 7.5 可观测
- 每次调用记录 token、耗时、成功 / 失败；任务级与日级成本汇总。

# 11. 风险与待定
- **竞品**：Grok Workhorse、worker-bridge 等已覆盖派活；需靠省 token 工具集与三种模式差异化，否则意义不大。
- **免费模型不稳定**：限流、下架频繁（例如多家免费额度近期缩水），工人能力波动大；路由与降级必须做好。
- **平台条款**：部分免费渠道禁止商用或对外中转（如魔搭 API-Inference）；工具只给用户本人自用，不做对外转售。
- **许可证**：Serena 只能复用 MIT 部分；worker-bridge、LooppooL、Nib、jcode 等许可证待核实后才能复制代码。
- **评测成本**：对照实验需付费模型，需先估预算。
- **主管侧依赖**：Hark 能否长期运行守护进程、能否挂 MCP，取决于宿主环境；CLI 模式是保底。
- **已定（v0.3 更新）**：已在 GitHub 公开开源（tangniutt/agentkit，Apache-2.0，2026-11-23 起）。**待定**：项目正式名称、正式版语言（Rust 还是 Go；2026-11-24 的内存调研结论是「先做 Python 速赢项，暂不重写」，见第 14 节）。
