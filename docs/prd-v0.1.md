# 1. 背景与目标

## 1.1 问题
现有编程工具（Claude Code、OpenCode、Cursor 等）是给人设计、再让 AI 去用的。AI 使用时最大的浪费不是写错代码，而是：

- 读了太多无关输出，上下文被日志、整文件、目录列表塞满；
- 编辑失败反复重试（匹配不上、缩进不对、改了不该改的地方）；
- 改完不知道对不对，要额外跑命令、再读一遍输出；
- 不了解别人已经怎么解决过同样的问题，从零推导，越写越偏；
- 长任务中途失忆，重复踩坑。

## 1.2 目标
做一套**人不用、AI 调用最顺手**的编程工具，以 MCP 服务器形式提供，任何 Agent（OpenCode、Claude Code、Cline、Pi、自研 Agent）都能直接挂载。

## 1.3 衡量标准（可量化）
同一模型、同一批任务，只换工具：

| 指标 | 目标 |
|---|---|
| 任务通过率 | 不低于 Claude Code / OpenCode 原生工具 |
| 总 token 消耗 | 降低 30% 以上 |
| 编辑一次成功率 | ≥ 99% |
| 每个任务的工具调用轮数 | 降低 20% 以上 |
| 无提示的静默失败 | 0 |

## 1.4 非目标
- 不做人用的界面（IDE、聊天窗口）。
- 不做 Agent 本身（规划、推理循环交给上层 Agent）。
- 不绑定任何模型或厂商。

# 2. 核心原则

1. **省上下文**：每个返回都有预算，超出就截断并告诉 Agent 怎么拿剩下的。
2. **不让 AI 猜**：错误信息说明原因并给出下一步建议；绝不静默失败、绝不假装成功。
3. **少而正交**：工具控制在 10–15 个，功能不重叠，避免 Agent 犹豫选哪个。
4. **先借鉴，再动手**：写代码前先找最接近的开源实现（见第 3 节）。

# 3. 强制流程：开发前先找参考项目

这是本工具的标配流程，适用于**用户交给 Agent 的每个开发任务**，也适用于**本工具自己的开发**。

## 3.1 流程
1. **理解需求**：把用户的需求提炼成 3–5 个关键词和一句话描述。
2. **搜索**：在 GitHub（按 stars、最近更新、许可证过滤）及相关社区搜索最接近的开源项目，候选不少于 5 个。
3. **评估**：每个候选给出相似度（高 / 中 / 低）、许可证、活跃度、可复用部分。
4. **克隆并索引**：把相似度最高的 1–3 个项目克隆到本地并建索引。
5. **检索实现**：写每个模块前，先查参考项目怎么做的，引用时注明出处。
6. **许可证检查**：
   - MIT / Apache-2.0 / BSD：可复用，保留版权声明；
   - GPL / AGPL：只借鉴思路，不复制代码（除非我们的项目也采用 GPL）；
   - 无许可证：视为不可复用，只看思路。

## 3.2 「新赛道」判定与告知
如果搜索一圈后**没有相似度为「高」或「中」的项目**，工具必须：

- 明确告诉用户：「没有找到接近的开源项目，这可能是一块新的、竞争少的赛道」；
- 附上搜索过的关键词、搜索范围和最接近的几个项目（及它们差在哪里），让用户自己判断；
- 提示风险：没人做可能是机会，也可能是需求不成立或技术难度高，建议先做最小样品验证。

## 3.3 本工具自身的参考项目（已调研）

| 项目 | 可借鉴部分 | 许可证 | 用法 |
|---|---|---|---|
| XERJ (xerj-org/xerj) | 代码搜索、跳定义/找引用、Agent 记忆、输出预算、远程 MCP | Apache-2.0（Query-1 模型闭源） | 直接作为搜索 + 记忆层接入 |
| Aider (Aider-AI/aider) | tree-sitter 仓库地图、改完自动 lint | Apache-2.0 | 借鉴代码 |
| SWE-agent (SWE-agent/SWE-agent) | 窗口式读文件、语法错误拒绝写入 | MIT | 借鉴代码 |
| Serena (oraios/serena) | LSP 符号级查找与编辑 | 主体 GPL-3.0，SolidLSP 库 MIT | 只复用 SolidLSP，其余借鉴思路 |
| Coding Tools MCP (xyTom) | 多文件补丁、权限分级 | 开源（待核实具体许可证） | 借鉴思路 |
| Nib | 按模型家族提供不同编辑格式、修复坏掉的工具调用 | 待核实 | 借鉴思路 |
| Claude Code | 唯一性替换、检查点回滚、子任务 | 闭源 | 只借鉴思路 |

结论：已有项目覆盖了约一半能力，**没有一家同时做到统一输出预算 + 编辑校验 + 自带评测**，这是本工具的差异点。

# 4. 功能需求

## 4.1 输出预算（所有工具共用）
- 每个工具返回默认上限 2,000 token，可由调用方指定。
- 超出时截断，并返回：总量、已显示范围、获取剩余部分的参数（如 `offset=200`）。
- 日志去重、折叠进度条和重复行；错误放在最前面。
- **验收**：任意工具在任意输入下返回不超过上限；截断信息 100% 存在。

## 4.2 编辑（edit）
- 精确字符串替换，要求唯一匹配。
- 匹配失败时返回最接近的 3 处候选及差异，而不只是「没找到」。
- 支持多文件原子补丁：要么全部成功，要么全部不动。
- 为弱模型提供行号 / 哈希锚点编辑模式，不需要逐字复写原文。
- 每次编辑后自动做语法检查；有语法错误的编辑默认拒绝写入，并说明原因。
- 返回：改动的 diff（受预算约束）+ 新增的 lint / 类型错误。
- **验收**：编辑一次成功率 ≥ 99%；语法错误写入次数为 0。

## 4.3 读取（read）
- 按行段读取，或按符号读取（「给我 `UserService.login`」）。
- 默认不允许一次读取整个大文件，超过阈值自动分段。

## 4.4 搜索与导航（search / symbol / repo_map）
- 接入 XERJ：关键词、语义、混合搜索，跳定义，找引用。
- repo_map：目录 + 每个文件的类 / 函数签名，几百 token 看全局。
- 搜索结果带 `文件:行号`，并提示索引是否过期。

## 4.5 执行（run）
- 带超时的命令执行；支持后台任务，可稍后重新获取输出。
- 返回结构化结果：退出码、stderr 尾部优先、耗时。
- 输出受预算约束，自动去重。

## 4.6 测试（test）
- 根据改动只运行受影响的测试（无法判断时运行全部并说明）。
- 返回：通过 / 失败数、失败用例名称、断言差异、堆栈中最关键的 5 行。

## 4.7 检查点（checkpoint）
- 每次编辑前自动快照（基于 git worktree 或内部快照）。
- 支持查看差异、回滚到任意检查点。
- 所有操作幂等：重复调用不会把同一处改两遍。

## 4.8 任务记忆（notes）
- 任务笔记：目标、已完成、待办、踩过的坑。
- 项目规矩：读取 AGENTS.md（测试命令、代码风格、禁区）。
- 长期记忆接入 XERJ `/_memory`，跨会话按含义召回。

## 4.9 参考项目（reference）
- 实现第 3 节流程：搜索 GitHub、评估相似度、克隆、索引、检索。
- 输出「参考项目报告」或「新赛道告知」。

## 4.10 子任务（delegate）
- 把独立子任务分给并行的子 Agent，返回摘要而不是全部过程。

## 4.11 错误信息规范
每个错误必须包含：
1. 发生了什么；
2. 最可能的原因；
3. 建议的下一步调用（含参数示例）。

# 5. 非功能需求

## 5.1 安全
- 在沙箱内运行；网络白名单。
- 密钥在网络层注入，Agent 看不到明文。
- 权限分级：读取不限；写工作区允许；删除仓库、推送、部署需人工批准。
- 远程 MCP 必须启用 Token 认证，禁止无认证对外开放。

## 5.2 兼容
- 协议：MCP（stdio + Streamable HTTP）。
- 已验证客户端：OpenCode、Claude Code、Cline；其余逐步验证。
- 系统：Linux 优先，其次 macOS / Windows。

## 5.3 性能
- 单次工具调用（不含命令本身执行时间）p50 < 200 ms。
- 增量索引：只重建改过的文件。

## 5.4 可观测
- 记录每次调用的 token 消耗、耗时、成功 / 失败。
- 提供类似 `xerj gain` 的统计：本次任务实际省了多少 token。

## 5.5 文档
- 工具 schema 从运行中的服务自动生成，CI 检查，防止文档与实际不一致。
- 提供 llms.txt：一段话让 Agent 自己完成安装配置。

# 7. 评测方案
- 任务集：50 个真实任务（含 SWE-bench Verified 子集 + 自建私有代码任务，私有任务用来体现参考编程的优势）。
- 对照组：同一模型分别使用 Claude Code、OpenCode 原生工具、本工具。
- 记录：通过率、总 token、轮数、编辑失败次数、耗时、成本。
- 每次发版都跑，结果公开，作为对外宣传的主要依据。

# 9. 风险与待定
- **许可证**：Serena 主体为 GPL-3.0，只能复用 MIT 的 SolidLSP；Coding Tools MCP、Nib 许可证待核实。
- **XERJ 依赖**：作为外部组件，版本变动可能影响接口；需固定版本。
- **评测成本**：对照实验需要调用付费模型，需估算预算。
- **差异化**：大厂（Anthropic、微软、Cursor）都在推 Agent SDK，本工具需靠「模型无关 + 省 token + 公开评测」立足。
- **待定**：项目名称、开发语言（建议 Python 起步，性能瓶颈处再用 Rust）、是否开源及采用的许可证。
